# Changelog

## Unreleased
- Desktop IDE: multi-cursor, snippets and configurable keyboard shortcuts. **Several cursors:** Ctrl+Alt+Down and Ctrl+Alt+Up add a cursor on the line below or above, Ctrl+D adds the next match of the selected word, Ctrl+Shift+L selects every match, Ctrl+Alt+click adds a cursor where you click, Escape goes back to one; typing, Backspace, Delete, Enter (keeps the indentation), Tab, paste (one line each when the counts match), copy, cut and the arrow, Home and End keys act at every cursor as one undo step; the status bar shows "N cursors". `FSharpened.Ide.Host/Cursors.fs` is pure (tested without a window). **Snippets:** the built-in snippets of the website core for every language plus your own VS Code-format files (`*.json`, `*.code-snippets`) in the data folder's `snippets` folder; type a name and press Tab, or *Snippets: Insert Snippet…* (`$` in the palette); Tab and Shift+Tab move between fields, copies of a field follow what is typed, Escape stops; lines take the indentation of where the snippet goes. `SnippetExpand.fs`, `SnippetFiles.fs`. **Shortcuts:** every shortcut is data (`Keybindings.fs`): the shipped table with your `keybindings.json` (VS Code's format: `{ "key": "ctrl+k", "command": "id", "when": "editorFocus" }`, a command starting with "-" removes a binding) laid over it; the Keyboard Shortcuts view (Ctrl+Alt+K) lists commands with their shortcuts, filters, and changes, removes or resets them; the menus and the palette show the shortcut in force. `Proc.run` no longer waits 3 s per call (and loses the output) when its caller has a UI context and waits for the result, which also made the Git window tests slow and flaky. Verified on win-x64 only (Host 276, Desktop 173 tests); not on the other five RIDs or macOS from here. Not done: multi-step chords (Ctrl+K Ctrl+S), `when` clauses other than `editorFocus`, snippet choices and transforms (the website core's limits), several cursors with the completion list.
- Desktop IDE: editor gaps closed (PLAN P7.8d). **Language server:** find references (Shift+F12, a results panel), document symbols as an outline view, signature help (Ctrl+Shift+Space, and on typing the server's trigger characters), code actions with a lightbulb and a Quick Fix menu (Ctrl+.), and server-side document formatting (Shift+Alt+F) that falls back to the language pack's formatter when the server cannot. Host: `LspFeatures.fs` (parsing and client members, tested against a scripted Python server). **Git:** `GitDiff.fs` (pure line diff) and `GitOps.fs` (git by argv through `Proc`, never a shell) give a diff gutter (added, modified, removed), a Source Control view with stage, unstage and commit, the branch in the status bar with switch and create, and per-line blame. Git and the language servers run only in a trusted folder. Every new control has an accessible name. Tests: host protocol tests, real temporary repositories, headless window tests. Verified on win-x64 only.
- Desktop IDE foundations (PLAN P7.8c, ADR-0023 amendment): `MainWindow.fs` is split into one class per concern with the pure decisions (paths, key map, brackets, disk sync, status text) in `Decisions.fs` and unit tests; the real window is tested headless with Avalonia.Headless (open folder, open file, palette, quick open, find and replace, search, theme, terminal toggles, save, trust prompt); every operable control has an accessible name, roles and landmarks, tabs, explorer and editor are reachable by keyboard (new commands next-tab, previous-tab, focus-editor, focus-explorer) with focus rings, and a test walks the tree and fails on an unnamed control; programs are found with PATH and PATHEXT and a Windows `.cmd` or `.bat` language server, debug adapter or tool starts through `cmd.exe /d /v:off /s /c` with quoted arguments, refusing quote, percent, line break and NUL. Fixed: the unsaved dot on the first edit of a tab, and choosing Search twice threw.
- Desktop IDE: the terminal is a real pseudo-terminal (PLAN P7.8). `FSharpened.Platform.Pty` starts the shell on ConPTY (Windows) or a pty (Linux, macOS) by P/Invoke; `FSharpened.Ide.Host` gains a VT screen emulator (`Screen`: colours, cursor moves, scroll regions, alternate screen, bracketed paste, device replies), `TermKeys` (key encoding) and `PtySession`; the window gets `TerminalView` (drawing, keys including Ctrl+C and arrows, resize, scrollback, selection, copy and paste). Colours and full-screen programs (vim, less, python's prompt) work. The pipe terminal stays as the fallback if no pseudo-terminal can be made (`FSH_TERMINAL=pipe` forces it). macOS is not run.
- Desktop IDE: file watching and fast search in Rust (PLAN P7.8a). New crate `native/rust/fsh-watch` (C ABI behind `FSharpened.Interop.Rust`): a recursive, debounced watcher that reports created, changed, removed and renamed paths in batches and ignores `.git`, `node_modules`, `bin`, `obj` and `target`, and a threaded text search with the managed engine's rules plus `.gitignore`. The Host binds it (`NativeLib`, `FolderSearch`, `FolderWatch`) with a managed search and a polling watcher as fallbacks, so the IDE never needs cargo. The explorer, Git status and open tabs follow changes made outside the IDE (reload, or a conflict question for unsaved edits), the status bar says which engine is running, and the `rust` stage of `fsh-ci` now runs every crate under `native/rust`. `fsh-ci` also stops handing a git hook's `GIT_DIR` and related variables to its children (a pre-push run made the Git status test see the pushed repository in a plain temp folder).
- Desktop IDE: rename and debugging (ADR-0024). **Rename** (F2, *Rename Symbol*): `textDocument/prepareRename` and `rename` in the language-server client, a preview of the files and lines that change with a confirm button, open files edited in place (one Undo) and the rest written through the workspace; a refused range or an overlap refuses the whole rename; a server without rename says so. **Debugging**: a Debug Adapter Protocol client (`tools/FSharpened.Ide.Host/Dap.fs`; stdio or TCP adapters), a `debug` block in language packs (adapter, build step, launch template; shipped for F#, C#, Python, Go, C, C++, Rust), a breakpoint gutter (F9), a DEBUG panel with call stack, variables and a console that evaluates, current-line highlight, F5 start or continue, F10, F11, Shift+F11, Shift+F5, a trust prompt and an install hint when the adapter is missing. **F5 now debugs; running a file is Ctrl+F5.** Tested against a scripted adapter (stdio and TCP), a scripted language server and real debugpy.
- Local CI/CD (`fsh-ci`, ADR-0016) hardened: a resource governor (usable memory and Windows commit headroom decide `--jobs` and MSBuild `-m:N`; preflight names the largest consumers instead of letting MSBuild crash), process-tree-safe timeouts and Ctrl+C, a single retry of build or test only when the failure is the machine's (never for a compile error or failed test; a recovered pass reports `WARN`), `--blame-hang` for tests, demand-driven restore and build (a docs-only change skips them), an atomic thread-safe cache keyed on the runner's own code, a fast file index, `web`/`gateway`/`hub`/`site` stages and a `--profile all` that covers `ide.yml`, `hub.yml` and `site.yml` locally, a `release` profile that writes a bundle with `SHA256SUMS` and `provenance.json`, and the commands `doctor`, `status`, `watch` and `verify`. There is deliberately no publish command. 78 self-tests.
- Desktop IDE (ADR-0023, Proposed): a native Avalonia application written in F#, `tools/FSharpened.Ide.Desktop`, with the website IDE's layout, colour roles and nine themes, a real editor with TextMate highlighting, folder tree with right-click menus, tabs, breadcrumbs, quick open, go to line and symbol, command palette, search in files, outline, status bar, save to disk with file watching, and Run with the output and problems panels. It reuses the F# core (`FSharpened.Ide`) directly. **Languages are data:** 37 language packs in `languages/*.json` (the eighteen website languages plus Go, Kotlin, Swift, Zig, Scala, Elixir, Julia, Perl, shell and common data and markup formats); adding a language is adding a file. The host library `FSharpened.Ide.Host` adds the pack engine, run plans, a local runner with a per-folder trust prompt, time and output limits, tool probes, a safe disk workspace, Git status, and a minimal language-server client (problems as underlines, completion, go to definition, a hover box). Also: replace in files (with include and exclude patterns; open files change in the editor so Undo works), replace in the open file, a line-based terminal (your shell on pipes, not a pseudo-terminal), and grammars for Haskell, OCaml, Elixir, Kotlin, Scala, Zig and TOML in `grammars/` (a file in `FSharpened/grammars` adds or replaces one). Not built yet: pseudo-terminal, debugger, Rust natives, split editors, VS Code extensions or Copilot. 73 new tests.
- Browser IDE, VS Code-style features (ADR-0022, Proposed): command palette (about 100 commands), quick open, go to symbol and line, search and replace across the project, outline and breadcrumbs, several cursors, line commands, snippets for every language, settings, nine built-in themes (two high-contrast), a status bar whose items open pickers, and right-click menus in the editor, file tree, tabs, project list and output (keyboard accessible; Shift+right-click keeps the browser's menu). **Import from VS Code as data:** `.vsix` (themes and snippets), theme `.json`, snippets files and `settings.json`; no extension code runs. **Download for VS Code** writes the project with `.vscode/settings.json`, `.vscode/extensions.json` (language extensions, `GitHub.copilot`, `GitHub.copilot-chat`) and a `.code-workspace`. GitHub Copilot and other extensions that run code cannot be hosted in a web page; the IDE says so instead of pretending. The F# core gained fuzzy ranking, search and replace, symbols, snippet templates, themes, settings and VS Code conversion modules.
- Browser IDE: eighteen languages (F#, C#, VB.NET, JavaScript, TypeScript, Python, Rust, Dart, C, C++, Go, Java, Ruby, Lua, PHP, R, Haskell, OCaml) running through two allowlisted backends, Compiler Explorer and Wandbox (ADR-0020, Proposed). The gateway routes each of 45 compiler ids to the backend that has it; only C, C++ and Rust take flags. Diagnostics from every language's real error format become editor markers. The tab strip scrolls and is grouped.
- New pillar `FSharpened.Interop.Rust` (Experimental): F# calls Rust through the C ABI, with the RID to target-triple table, a strict native-library resolver, a cargo build plan and reader that wrap cargo, and ABI conventions with a tested reference crate. `fsh doctor` reports the Rust toolchain. CI gained a `rust` stage and `--require-rust` (ADR-0019, Proposed).
- `ide/web` has tests that run the Fable-compiled core against captured compiler output.
- ADR-0021 (Proposed) sets the roadmap for projects, community projects, cross-language linting, Workers AI, rust-rtpc and fsharpened-rtpc, atomic and self-healing FSharpened, and the code-only agent with its training desktop; `PLAN.md` gains Phase 6.
- IDE core: a polyglot project model (`Project.fs`), whole-project statepoints (`ProjectState.fs`, `StateTimeline`), and a ZIP codec with project import and export (`ide/web/src/archive.js`, `projectio.js`), all tested.
- IDE page: projects replace the single-language workspace. A sidebar with a file tree and a project list, open-file tabs, create, rename or move, delete, set entry, copy, download a file, a folder or the whole project as `.zip`, import a `.zip`, a folder or files (button or drop) with a report of what was left out, several projects saved in the browser, whole-project snapshots, whole-project share links. Programs from before projects are kept as the project "My workspace". The Reset button is gone: **Projects → Examples** makes a fresh starter project and nothing is overwritten.
- Initial skeleton: specification, registry, governance, agent operating system, project skeletons for 28 pillars and 2 tools. No functional release.
