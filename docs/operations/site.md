# Website and installable apps (PWA)

Two installable web apps: the public site with its IDE (https://fsharpened.pages.dev) and the hub admin console (https://hub.fsharpened.workers.dev, see `docs/operations/hub.md`). Both are plain static files plus one service worker each. No framework, no runtime dependency, strict CSP (no inline script or style anywhere).

## Layout
| Path | Role |
|---|---|
| `site/src` | hand-written `site.css`, `site.js`, `theme.js`, `ide.css`, and `sw.js` (a template: the build injects the version and file lists) |
| `site/static` | copied as is: `_headers`, `favicon.svg`, `assets/` (mark, og image) |
| `branding/icons` | generated by `tools/site/icons.py` from the mark's geometry: any, maskable, Apple and favicon sizes (also copied to `worker/admin/`) |
| `site/dist/ide.js` | the IDE bundle (`cd ide/web && npm run build`; generated, git-ignored) |
| `tools/site/build.py` | writes `site/public` (generated, git-ignored): pages, fingerprinted assets, manifest, `sw.js`, sitemap |
| `tools/site/check.py` | build verification, run by CI (`.github/workflows/site.yml`) |
| `site/test` | service-worker tests that run the real `sw.js` files against a mocked Cache API |

## Build, check, deploy
```bash
dotnet tool restore && (cd ide/web && npm ci && npm run build)    # IDE bundle -> site/dist/ide.js
python tools/site/icons.py --check                                # icons match the mark (omit --check to regenerate)
python tools/site/build.py --require-ide                          # -> site/public
python tools/site/check.py                                        # links, metadata, manifests, precache, CSP-safe markup
node --test "site/test/*.test.mjs"                                # service workers (site and hub)
npx --prefix gateway wrangler pages deploy site/public --project-name fsharpened --branch main   # maintainer
```
`SITE_URL=https://example python tools/site/build.py` changes the canonical and sitemap origin.

## Adaptive design rules
- Layout is fluid from 280px phones to ultrawide: `rem` units, `clamp()` type, grids sized with `min(100%, N rem)` so nothing forces horizontal scroll, `100dvh` with a `100vh` fallback, `viewport-fit=cover` plus `env(safe-area-inset-*)` for notches and rounded corners.
- Input adapts: `pointer: coarse` raises targets to 44px and form fields to 16px (stops iOS zooming in); everything works from the keyboard (visible focus, arrow-key tabs, a keyboard-operable splitter, Escape then Tab leaves the editor).
- Display adapts: light, dark and automatic theme (saved in `fsh-theme`, set before first paint); `prefers-reduced-motion`, `prefers-contrast`, `forced-colors` and print are handled; the navigation collapses to a menu only when JavaScript is available.
- Compatibility: ES2020 bundles (esbuild targets Chrome 87, Edge 88, Firefox 78, Safari 14); newer CSS (`color-mix`, `dvh`) always has a plain fallback. Pinch zoom is never disabled.
- Reduced motion uses `transition: none`, not a tiny duration: a 0.01ms transition still animates `font-size` for a frame and CodeMirror measures text during it (misaligned line numbers).

## How the service worker behaves (site)
- Core pages and the shared CSS/JS are precached at install, so reading works offline after the first visit. The IDE bundle is cached the first time the IDE opens, not up front.
- Pages: network first (3.5s timeout), then the last copy you saw, then `/offline`. Files under `/assets/h/` carry a content hash in their name and are cache-first forever. Other same-origin files revalidate in the background.
- Other origins (the IDE gateway) and `sw.js` itself are never intercepted. A new version activates at once; open pages keep the files they have and `site.js` offers a reload.
- Because HTML is revalidated and assets are fingerprinted, a deploy can never mix old markup with new scripts.

## The hub console
`worker/admin` has its own manifest and `sw.js`. It caches only the app shell. **`/api/*` is never intercepted or stored**: it carries private run history and tokens, and the GitHub sign-in is a redirect that a worker must not touch. Offline, the console opens and says so; it reloads itself when the connection returns. If you add a shell file, add it to `PRECACHE` in `worker/admin/sw.js` (a test checks each listed file exists).

## Verifying in a real browser
Automated checks cannot register a service worker in a browser, so do this once per release in Chrome or Edge (the in-app browser pane of the Claude desktop app cannot register service workers):
1. DevTools, Application: Manifest shows no errors and the icons render; Service Workers shows one activated worker.
2. Lighthouse (PWA and Accessibility) passes on `/`, `/ide/` and the hub.
3. Application, Service Workers, tick Offline, reload: pages already visited open, `/never-seen` shows the offline page, the IDE's offline checks still run.
4. Install from the address bar; the app opens standalone and `Run` still works online.
5. On iPhone: Share, Add to Home Screen (iOS has no install prompt; the Install button shows a hint instead).

## Not built, on purpose
Manifest screenshots, share targets, file handlers and push or background sync. None is needed for installability, and each adds a permission or a data path the project does not want yet.

## Troubleshooting
- *A user sees an old site:* workers are network-first, so this only happens offline. DevTools, Application, Storage, "Clear site data" resets it.
- *Install button missing:* the browser decides (Chrome needs an active worker, a manifest with 192/512 icons and engagement); `python tools/site/check.py` verifies everything the project controls.
- *IDE blank after deploy:* the page loads `/assets/h/ide.<hash>.js`; deploy `site/public` whole, never a subset.
